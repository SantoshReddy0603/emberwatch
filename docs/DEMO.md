# Four-minute demonstration

Prepare three separate browser sessions: Administrator, North ranger, and East ranger. Tabs can keep distinct sessions, but separate browser profiles or private windows make the roles clearer. Run the simulator at 2 Hz with chaos off initially. Keep the map attribution visible.

| Time      | Action and explanation                                                                                                                                                                                                                                                                                                                                     |
| --------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 0:00–0:35 | Show the administrator overview. Explain that 420 virtual forest sensors and 8 weather stations generate current readings continuously. Point to live counts, map, selected-source temperature/smoke, and the simulation label.                                                                                                                            |
| 0:35–1:10 | Show North and East ranger sessions. Their source counts and zone filters reflect assigned access; neither exposes the administrator controls or pipeline metrics. Leave both connected.                                                                                                                                                                   |
| 1:10–2:05 | In administrator controls, set a wind direction/speed, choose **Ignite on map**, and select a point near a dense cluster of North sensors. Observe rising heat/smoke and sustained incidents. Neighbor confirmation takes time; do not present a single spike as confirmed wildfire. Show North receiving its incidents while East remains scoped to East. |
| 2:05–2:40 | Open an incident timeline and acknowledge it as the North ranger. Show that acknowledgment records a response while the condition stays active. In administrator controls choose **Extinguish**; recovery requires subsequent clear readings, and failed sensors may remain offline.                                                                       |
| 2:40–3:20 | Select a source, switch between 15-minute and 1-hour history, pause/resume the chart, then show the zone history scrubber. Explain that an empty database only contains history accumulated since startup;24-hour retention does not invent 24 hours of data.                                                                                              |
| 3:20–4:00 | Show metrics and the recorded performance report. Optionally enable chaos and raise the requested rate to 10 Hz to show duplicates/rejections, backpressure, and independent client subscriptions. Distinguish current UI rates from the separately measured 50-client test. Return to 2 Hz, disable chaos, and extinguish before ending.                  |

The simulator is stochastic and some sensors can fail in a fire. Allow time for a developing event; move the ignition near another sensor cluster if the first location has few neighbors. Spread arrows describe apparent motion inferred from tripped sources, not a ground-truth forecast. The danger score is a composite 0–100 indicator.

Record the working application and role separation. Explain the queued-ingestion ACK, unique event identity, history/live merge, and bounded client rendering when discussing reliability. Do not claim every intermediate reading is pushed to each browser or that the local benchmark guarantees hosted performance.
